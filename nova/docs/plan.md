# Nova 向けモジュラーシンセ：RackDroid 改造計画

## Context

Retroid Pocket Nova（Android 13、4.5 インチ 4:3、1280×960）で、ボタンでも快適に使えるモジュラーシンセを動かしたい。きっかけは TrimUI 向けの brickrack だったが、調査で **RackDroid**（VCV Rack 2 の Android 移植、GPLv3、v0.1.3.9）が見つかった。

RackDroid には、希望のうち次がすでにある：音、`.vcv` の完全互換、USB / Bluetooth MIDI、WAV 録音、画面オフ再生、タッチ鍵盤、Mutable 系 20 モジュール＋Grids 相当。

足りないのは次の 5 つで、これを足すのがこの計画：

1. ボタン操作（いまはボタンとスティックの入力を捨てている）
2. スティック・L2/R2 を CV にする仕組み
3. 傾きセンサーを CV にする仕組み
4. タッチの XY パッド
5. Mac との手軽なパッチ受け渡し

brickrack の移植は見送る。

## 方針

- **土台**：`nowheel/RackDroid` を `~/Documents/Projects/nova-modular/` に直接 clone し、`nova` ブランチで作業する。GitHub への公開や push はしない（ローカルだけ）。節目ごとにローカルでコミットする。
- **公式版と並べて入れる**：アプリ ID に接尾辞を付けた別アプリにし、アプリ内アップデーターは止める。公式版に上書きされるのを防ぎ、公式版を比較用に残す。
- **触る範囲**：`native/port/`（移植層）と `app/`（Kotlin）だけ。`third_party/`（VCV Rack 本体やプラグイン）は触らない。追従しやすいよう、できるだけ新しいファイルに書き、既存ファイルへの変更は呼び出し口だけにする。
- **コントローラー類は VCV 標準の「Gamepad」MIDI ドライバとして見せる**：スティック、L2/R2、傾き、XY パッドを 1 つの仮想ゲームパッドの軸にまとめる。VCV 標準の MIDI-CC→CV や MIDI-Map でそのまま CV にでき、専用モジュールが要らない。パッチは Mac の VCV Rack でもそのまま開ける。
- **タッチはそのまま残す**：ボタンとタッチを併用できるようにする。既存の機能は減らさない。

## 操作の割り当て（案）

brickrack と同じ考え方で、「演奏に使う入力」と「操作に使う入力」を固定で分ける。モード切り替えなしで両方使える。

```
   [L2] 演奏：CV（押し込み量）        [R2] 演奏：CV（押し込み量）
   [L1] 操作：前のモジュール          [R1] 操作：次のモジュール
 ┌──────────────────────────────────────────────────────────┐
 │  (左スティック)                                  (Y)      │
 │  演奏：CV X/Y                                (X)     (A)  │
 │  押し込み L3：ゲート        ┌─────────┐          (B)      │
 │                            │  画面   │                    │
 │   [十字キー]               │ タッチ可 │   (右スティック)   │
 │   操作：フォーカス移動      └─────────┘   操作：つまみを回す│
 │                                          押し込み R3：ゲート│
 │         [Select] ズーム切替     [Start] メインメニュー     │
 └──────────────────────────────────────────────────────────┘
   本体の傾き → 演奏：CV
```

| 入力 | フォーカスが… | 動作 |
|---|---|---|
| 十字キー | — | 近くのつまみ・ジャックへ移動。端では隣のモジュールへ |
| A | つまみ | 編集モード（↑↓ 粗く、←→ 細かく）。もう一度 A か B で終了 |
| A | スイッチ・ボタン | 切り替え。押している間だけオン（モーメンタリー） |
| A | ジャック | ケーブル開始 → つなげられるジャックだけを移動 → A で接続 |
| B | ジャック | そのジャックのケーブルを抜く。配線中はキャンセル |
| X | — | モジュール追加 |
| Y | つまみ | 初期値に戻す。それ以外ではモジュールのメニュー |
| 右スティック | つまみ | 直接回す |
| Start | — | メインメニュー（File / Edit / View / Engine、MIDI、鍵盤、録音、XY パッド） |
| Select | — | ズーム切替（全体 / モジュール 1 つ / 最大） |

画面下に「モジュール名 › つまみ名　値」を常に表示する。割り当ては実機で触って調整する。

## マイルストーン

各段階の終わりに実機で確認し、使い心地を聞いてから次へ進む。

### M0　準備と試用（開発なし）

- Android のビルド環境を整える：コマンドラインツール、NDK 27.2、CMake 3.22.1、API 35。Android SDK のライセンスに同意して導入する（数 GB）。JDK は Android Studio 同梱の 21 を使う。
- Nova の USB デバッグを有効にして Mac につなぐ（手順は場所を示して案内する）。
- 公式 RackDroid の APK と Audible Instruments・Valley のパックを `gh release download` で取得し、adb で入れる。
- タッチで触って確かめる：4.5 インチでの見やすさ、音の遅れ・途切れ。
- 実機の情報を採る：画面密度、コントローラーの名前とキーコード（十字キーがキーか軸か、L2/R2 の軸）、オーディオの低遅延対応、MIDI・USB ホスト対応。
- **判断**：タッチで触って「これを土台にしてよい」となれば M1 へ。

### M1　ソースからビルドして動かす

- clone、`nova` ブランチ作成、アプリ ID の接尾辞とアップデーター停止（`app/build.gradle.kts` の `-PtestBuild` の仕組みを流用、`AppUpdates.kt`）。
- 無改造でビルドして Nova で起動し、公式版と同じに動くことを確かめる。
- Mac でビルドが通らない場合は、原因を突き止めたうえで Docker（Linux）でのビルドに切り替える。
- `CLAUDE.md`（ビルドと実機確認の手順）を置く。

### M2　スティックと L2/R2 を CV に

- `native/port/gamepad_input.{hpp,cpp}`（新規）：`main_android.cpp` の `handleInput` で入力元を見て、ゲームパッドのキーと軸を状態として持つ。いまジョイスティックの動きがタッチ扱いで捨てられている処理（`touch_input.cpp`）を直す。
- VCV 標準の Gamepad ドライバを復活：`third_party/Rack/src/gamepad.cpp` をビルドに加え（`native/CMakeLists.txt`）、必要な 4 つの関数を `glfw_stub.cpp` に実装し、`gamepad::init()` と `step()` を呼ぶ。
- 確認：MIDI-CC→CV で左スティック → VCO の音程、L2 → VCA、のパッチを作って鳴らす。

### M3　ボタン操作（最大の作業）

- `native/port/gamepad_nav.{hpp,cpp}`（新規）：フォーカスの管理、移動、フォーカスの枠と下部の表示。
- 使い回す既存の部品：
  - つまみ・ジャックの列挙（`label_overlay.cpp` のやり方）
  - 重ね描き（`selection_glow.cpp` のやり方）
  - モジュールへのスクロール（`bookmarks.cpp` の `startJump`）
  - 近いジャックの検索と接続、つなげられるジャックの強調（`cable_park.cpp`）
  - モジュールの配置（`browser_native.cpp` の `chooseModel`）
- つまみは仮想マウスではなく値を直接変える（どのメーカーのモジュールでも同じに動く）。値の変更と配線は Undo に積む。
- メインメニューは新しいダイアログで作り、既存のツールバーと同じ処理を呼ぶ（`menu_native.cpp`）。ツールバー自体はタッチ用のまま残す。
- モジュール追加のパレット（`ModulePalette.kt`）をボタンで選べるようにする。
- VCV 本来のキー操作（スクロール、ズーム、削除）への経路も足す。USB キーボードも使えるようになる。
- 4:3 の小さい画面向けの調整：ツールバーは最初は畳む、など。
- 段階を分ける：①移動とつまみ → ②配線 → ③追加・メニュー。それぞれ実機で確認する。

### M4　傾きセンサーと XY パッド

- `native/port/sensors_android.cpp`（新規）：傾きを仮想ゲームパッドの追加の軸にする。オン・オフと「いまの角度を中心にする」をメニューに置く。
- `XyPadView.kt`（新規、`PianoKeyboardView.kt` のやり方を踏襲）：タッチの X・Y・押下を追加の軸とボタンにする。

### M5　Mac との受け渡しと MIDI の実機確認

- パッチを Mac から扱える場所に置く。`Documents/RackDroid/patches` を使う案を第一候補とし、コードを読んで決める。フォルダからパッチを開く操作を足す。
- Mac 側に、adb でパッチを送受信する小さなスクリプトを `nova/tools/` に置く。
- VCV Rack との往復を確認：Nova で保存 → Mac の VCV Rack で開く、その逆。
- MIDI を 4 通り確認し、動かないものは原因を調べて直す：
  1. USB キーボード → Nova
  2. Nova → 外部の機器（ノートとクロック）
  3. Mac の DAW と USB 接続
  4. Bluetooth MIDI
- 使い方のドキュメント（画像つき）を `nova/README.md` に書く。

### M6　足りない 4 モジュール（任意・あとで判断）

Beads / Peaks / Edges / Blades と Plaits の 24 エンジン版を、brickrack の実装をもとに RackDroid 用のパックにする。M5 まで使ってみて、必要なら着手する。

## お願いすること

- Nova の USB デバッグを有効にして Mac につなぐ（M0）
- Android SDK のライセンス同意と数 GB の導入の了承（この計画の承認に含める）
- 各段階での使い心地の確認
- MIDI の確認に使う機材の用意（M5）
- Mac の VCV Rack に Audible Instruments を追加（VCV のアカウントが必要、M5）

## リスク

- **ボタン操作の快適さ**：VCV のパネルは密度が高い。M3 を 3 段階に分け、実機で触りながら詰める。
- **入力の届き方**：十字キーや L2/R2 がどのキー・軸で届くかは機種しだい。M0 で実測してから作る。Home や M1/M2 はアプリに届かない可能性がある。
- **Mac でのビルド**：公式の CI は Linux。通らなければ Docker に切り替える。
- **本家の更新**：2〜3 週間ごとに更新される。変更を新しいファイルに寄せ、節目で取り込む。
- **音の遅れ**：端末のファームウェアしだい。M0 で確かめる。

## 検証

- **ビルド**：Android Studio 同梱の JDK 21 と `~/Library/Android/sdk` を指定して `./gradlew assembleSideloadRelease -PdevKeystore`（＋別アプリ用の指定）。
- **実機の確認ループ**：SDK 側の adb を使う（PATH 上の古い adb と混ぜない）。`adb install -r` → `adb logcat` → `adb exec-out screencap -p` で画面を取得して目視。
- **ボタン操作**：`adb shell input keyevent` でキーを送り、フォーカスの移動・つまみの値・配線を画面で確認する。スティックと傾きは手で動かしてもらう。
- **CV**：スティック → 音程のパッチを録音し、WAV を Mac に取り出して、音程が動いていることを解析で確かめる。
- **VCV 共有**：同じパッチが Nova と Mac の両方で開いて鳴ること。
- **既存機能が減っていないこと**：タッチ操作、鍵盤、録音、画面オフ再生、MIDI を各段階の終わりに確認する。
